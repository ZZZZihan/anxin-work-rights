# 安薪乐业检索评测任务 v1

这是从项目冻结公开资料构造的 128 条检索任务，用于记录当前检索器的基线、保留失败样本，并为后续算法变更提供同一套比较输入。题面由 Agent 逐条编写；相关记录和出处由 Agent 对照本地来源段落核读。它不是实际用户提问日志，也没有经过人类法律专业人员审核。

标注过程没有运行当前检索器，也没有查看已有或后来生成的检索排名，没有根据命中结果改题、选 gold 或划分数据。集成后的本目录可以同时保存基线生成工件，标注与评测结果通过任务哈希对应。

## 文件与冻结范围

- `tasks.jsonl`：每行一条任务，共 128 行；SHA-256 为 `8f246287cc124d0d2da8007f84fd0d6bb8a2a5031c88a03cd0cea0fdadf027c0`。
- `manifest.json`：任务文件 SHA-256、来源数据指纹、批次、修订理由、数量和测试分组清单。改动任务必须重新记录指纹，并说明原因；旧实验继续绑定原任务哈希。
- `validation-report.json`：逐字段结构检查、每题 gold 的出处归属与覆盖情况、分组检查及 Agent 核读范围。它不代表完整语义审核或法律专家认可。
- `history/initial-90.tasks.jsonl`、`history/initial-90.manifest.json`：初版 90 题的原始快照；`history/revised-90.tasks.jsonl`：只修订 3 条 split 后的 90 题快照。历史文件不作为当前评测输入。
- `baseline.json`、`baseline.md`：集成后由 `scripts/eval-public-retrieval.mjs` 生成的机器记录和阅读报告。`npm run eval:retrieval` 生成基线，`npm run eval:check` 重放核对；本标注工作没有执行这两个命令或读取其输出。
- 当前来源是 `../labor-public-v1/release/` 中的 `sources.jsonl`、`cases.jsonl` 和 `provisions.jsonl`，以该 release 的 manifest 为边界；128 题绑定的来源数据指纹为 `94593cc65bc34e1d739f22b6a66c95e19ff768e083f435bada899fc86309ac8e`。
- 原始 90 题按旧 release 核读，覆盖原 14 个案例及 24 条文任务用到的来源条文段落；追加 38 题对照新增 19 案的 `curation/cases/cases.json`、`coverage.json` 和冻结原文段落核读构造。对应 curation 文件哈希记录在 manifest 和核查报告中。
- 当前知识库共有 33 个案例、8 部法规、54 条精选条文；题集覆盖全部 33 案和 31 条已标注相关条文记录，并不声称逐条覆盖全部 54 条文。

原网页的发布机构、地址、日期和原始页面哈希保留在来源数据中，本目录用稳定的 record ID 和 paragraph ID 引用它们，不另行复制网页。原资料是官方典型案例和法规页面，并非真实用户案卷或原始证据附件。免费公开访问不等于开放再分发许可，沿用来源数据的用途与版本限制。

## 构造与分组

| 任务 | 数量 | dev | test | 分组单位 |
| --- | ---: | ---: | ---: | --- |
| `case_retrieval` | 94 | 64 | 30 | 原记录 `case_group_id`；原 14 案每案 4 题，新增 19 案每案 2 题 |
| `provision_retrieval` | 24 | 18 | 6 | 主要标注法规的 `law_id`，每法 3 题；关联 gold 法规同时约束 split |
| `no_answer` | 10 | 6 | 4 | 5 个域外情境族，每族 2 题 |
| 合计 | 128 | 88 | 40 | 46 组 |

测试任务占 40/128，即 31.25%。同案衍生表述、同部主要法规的题目、同个无答案情境族均只在一个 split 内；新增 19 案中 7 案分到 test、12 案分到 dev。测试分组的准确 ID 见 manifest，标注者未用检索排名决定划分。案例题使用口语改述、证据使用问题、主体区分、正反结论和公开程序经过等角度，不从标题统一套模板。类比情境有时使用匿名甲乙或口语表达；它们不是对原案件新增事实的报道。

条文任务的 `groupId` 仍为主要法规，但不能仅凭主要法规分组：同一 gold 法规在任何条文任务出现时都必须属于同一个 split。当前跨法 gold 连接出两个集合：确立劳动关系通知、劳动合同法、解释二、劳动法、保障农民工工资支付条例、工资支付暂行规定同为 dev；仲裁法和解释一同为 test。这项约束针对条文 gold，不宣称案例引用法规也按 split 隔离。

所有 33 个案例都被覆盖，包括众包骑手、主播、代驾等不支持劳动关系的案例。原资料已有否定结论仍属于有答案任务，不能因为劳动者请求未获支持而标作 `no_answer`。

新增 19 案中有 12 案在 coverage 中标为 `merits_supervision_eligible=false`，对应 24 题只问公开执行、破产、调解、协商或督促过程及其披露结果，不把它们用作实体关系或责任裁判监督。股东案只写启动追加申请、释明、付款及撤回申请；实际控制人案只写查证和限制消费促成付款；网约车案不从调解推出劳动关系成立；退休返聘案不推定劳动关系成立或全部款项已经履行；48 人案不补写进入速裁通道的 4 人最终结果。

`no_answer` 只表示本冻结资料无可支持的记录。这 10 题分别涉及消费品售后、图片软件操作、烹饪、天文、园艺。提到“聊天截图”“银行流水”的软件操作题，也不应因为资料里出现这些名词就返回劳动争议资料。这里不测试一般内容拒绝策略，不把证据不足以裁判个案等同于资料完全无关，也不声称这 10 题代表真实域外查询分布。

## 字段与 gold 解释

任务字段为：`id`、`taskType`、`split`、`groupId`、`query`、可选 `topic`、`expectedRecordIds`、`expectedCitationRefs`、`annotationStatus`、`rationale`。所有记录的审核状态固定为 `agent_curated_not_legal_expert_reviewed`。

正例至少有一个已核读的相关记录。已知相同规则在多条记录中出现时，尽量同时列入：例如三类加班比例分别见劳动法和工资支付规定。每个 gold 记录至少有一段列入 `expectedCitationRefs`；这些段落必须属于对应记录自己的 `source_refs`（案例）或 `refs`（条文），并且确实支持题面所问。空答案任务的两组 gold 数组均为空。

gold 是“已核读的相关正例集合”，**不穷尽所有相关记录**。没有列入 gold 的记录不因此被证明不相关。仅凭此数据不能计算可信的 precision、法律正确率、胜诉率，也不能把未命中 gold 直接判为回答错误。`rationale` 解释标注依据和条件边界，不是模型标准答案。

## 运行边界与防泄漏

本基线检索调用只接收 `query` 和统一的 K=6，与当前业务 API 仅按 query 检索的行为一致。`topic` 仅作统计标签，不传给检索器；`taskType` 可供评测器分组报告，但不得拿它为单题修改排序、只留目标类型或特殊过滤。`expectedRecordIds`、`expectedCitationRefs`、`rationale`、`groupId`、`split` 和任务 ID 都只供评测与审计，不能进入检索函数、重写提示词、模型上下文或排序特征。

K=6 沿用当前检索默认值；如后续实验采用其他 K，应在实验配置中明确记录，并对所有题一致。正例可报告命中任一已标注相关记录的 Hit@K、首个已标注相关记录的 MRR@K、已标注正例的 Recall@K；这些都是相对于不穷尽 gold 的诊断指标。条文查询和案例查询应分别报告，不能把返回另一类型的近主题记录自动算作命中。无答案题应独立报告空结果比例及误返回，并检查失败题实际返回了什么。引用检查只能说明已知出处是否随命中记录可追溯，不能证明语义蕴含或法律适用正确。

这是**任务分组**后的 dev/test，不是把来源文档从检索库中移除。两个 split 都使用完整知识库；案例与法规也可能讨论同一规则，同一来源汇编中的不同案例可能分属不同 split。因此不能称为未知法规、未知主题或未知网页上的泛化测试。test 题公开可见，只有在开发中不使用其得分和失败详情调参时，才能维持一次相对独立的比较；一旦据此调参，应如实标记并另建新留出任务。

## 批次与修订记录

初版 90 题哈希为 `c2f12cfd9bfc50e5e0aa4ec7789d64a29bfc77d75bde63656f7b7b12689f0684`，来源指纹为 `e599f7f44e0350378c8369a0bf98932ffb15c111bd7d2d867402584104d8ad7a`。发现仅按主要法规分组会令 dev 中加班、按月支付、节假日发薪等题的 gold 工资支付规定与该法规自身的 test 题跨 split，故将 `labor-eval-provision-08-01` 至 `08-03` 的 split 从 test 改为 dev。其余 87 题全部字段、这 3 题除 split 外全部字段不变，包括 ID、query、gold 数组、topic 和 rationale。修订后的 90 题哈希为 `a6c8ef40a72ae8c1efe61e9dd6a448b6b5765a808fee8a29921f0de36b311e94`，数量为 dev 64 / test 26。

随后按新来源的 19 个案例组追加 38 题（ID `labor-eval-case-15-01` 至 `labor-eval-case-33-02`），没有删除或按检索效果重写旧题；最终为本版本 128 题。来源扩大和 split 修订都会影响可比较范围，旧 90 题实验应继续绑定旧哈希，新基线应使用 128 题及新来源指纹。保留全部成功与失败轨迹，不通过删除难题、改 gold 或改 split 提高基线。任何后续标注纠正继续保留修订理由、旧任务指纹和需要重新评测的版本范围。
