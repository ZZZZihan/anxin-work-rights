## 行为与证据

- 原版 timeout/503/JSON解析错误均把健康任务写failed并取消。新版本保留running与原任务ID；连续通信异常最多60秒，正常running清除异常窗口。明确终态失败和超过31分钟总生命周期仍终止并清理。31分钟覆盖3个串行任务各10分钟及1分钟余量，旧starting记录保持60秒兼容。
- UUID在调用服务前写入D1；POST回执丢失后按原ID查询，不自动重提，不生成候选或确认。提交期间的来源变化继续409，已知ID可取消。
- 服务同ID/同完整source返回同一个任务，同ID换source为409；未知ID先DELETE会记录取消，迟到POST为410。完成结果5分钟过期后也保留31分钟ID记录。1024条有界记录，已接纳任务预留取消位置；满容量新任务/未知取消为429，不驱逐未过期记录。
- 独立D1原20项为7通过/13失败；初版对扩展24项仍有两个数组status错误，改为严格字符串后最终26/26通过。并发诊断记录也已验证只写一次revision。集合扩展分别记录，没有假称同规模比较。
- 新增服务8项基线0/8，修复后8/8；实际服务HTTP覆盖丢弃首次回执后同ID重试、部分POST请求体尚未完整时先DELETE。
- 新增实际Worker/D1/R2/rules HTTP9场景基线2通过/7失败；整合独立检查9/9。后两组基线400只是尚不支持新协议，不冒充旧版已满足410/202语义。SIGTERM冒烟明确报告FAIL/exit1，临时目录清理成功，不能留下旧PASS。
- root完整 `npm run check` exit0：187 Vitest，30 Node fact-runtime，材料60项中59通过/1平台条件跳过，Python/类型/lint/构建/数据检查通过。最终root HTTP结果单列，独立HTTP先于status类型的最后防御，不混称同一文件哈希。
