# 完成结果保留期与持久任务恢复窗口一致

对应 PR #36 审查评论 4305379844，基线 `d14cbd44e20952afe58274c4c28cfc54f19ad902`。原服务在任务完成后 5 分钟删除结果，而持久任务允许从提交时起恢复 31 分钟：页面关闭或休眠 6 分钟后，已成功提取的原始回答会丢失。此前绿 CI 未覆盖这个时间组合。

产品改动仅将 `scripts/fact-jobs.mjs` 的完成结果保留期改为 31 分钟，从每个任务自己的 `finishedAt` 计算。取消继续立即隐藏/删除结果；过期后保留 31 分钟 ID 防重放记录；32 个任务及 1024 条 ID 上限保持不变。D1 的提交起 31 分钟上限不变，达到边界即失败并取消，不将迟到结果变成可用事实。服务结果保留到完成后 31 分钟，足以覆盖这个有效恢复窗口。

- 服务侧针对回归 7 组：基线 2 通过/5 失败，修复后 7/7 通过。覆盖 6 分钟恢复、31 分钟精确边界、三项排队任务分别在 10/20/30 分钟完成、取消后丢弃迟到输出、32/1024 容量与过期恢复、失败状态保留。既有 `fact-jobs` 整文件 38/38 通过。
- 未参与该实现的 Agent 新建 7 项实际事实路由 + 临时 D1 + 真实队列测试：基线 4 通过/3 失败，只替换服务 TTL 后 7/7 通过。6 分钟和 30 分 59.999 秒恢复保留原始回答，并发返回只入库一次；恰好或超过 31 分钟不轮询、不导入，按失败取消；排除材料和早先取消不能复活结果。

原模型输出、冻结实验与 store 逻辑未更改。内存队列仍不能跨服务进程重启或跨实例恢复；无人读取时原始回答最多保留完成后的 31 分钟，容量满仍返回 429。这是有界软件恢复能力，不是永久结果档案、真实模型新评测、真实案件业务验收或生产部署。
