## 原版复现与最终行为

| 风险 | 可达最小例（模型只引用金额） | 修复后的运行时行为 |
| --- | --- | --- |
| 班组误作个人 | `王甲班组十名工人，2024年7月应付工资合计80000元` | 原始候选保留；个人总额 values 为空，需核对主体 |
| 主体/期间跨事件拼接 | 王甲7月尚未结算；李乙8月完整应付80000元，模型却填王甲/7月 | 要求同一锚定事件的单个主体、完整期间、明确总额关系；不从其他句/块借文字 |
| 部分应付误作完整 | `王甲2024年7月部分应付工资80000元` 或金额后接 `加班工资另计` | due_total 与 paid_total 均受完整性约束；未知后置说明也不能默认为完整 |
| 外币尾缀被裁掉 | `8000港元`、`8000美元`、`8000 USD` 只返回 `8000` | 精确人民币 amount 降为 null、unsupported；原始金额和引文保留 |

主体关系采用有限的明确语法：单个劳动者→完整工资期间→明确完整应付/已付→唯一金额。源文前后分句和 OCR 文本块的表头、尾注、同主体说明也参与可用性检查；另一行工资记录不能遮蔽全局表头。无法分离的上下文追加 `source_relation_unresolved`，不再进入可用个人总额提示。精确数值本身可保留用于阅读，但不代表主体或完整性被确认。

附着币种检查覆盖前后缀、括号、Unicode/全宽符号、地区字母加货币符号（US$/HK$/S$/A$等）及财务中文数字；rate/other_money 也直接校验 amount=null，不能靠总额门槛掩盖币种错误。修复运行时“8000人民币”误作8000人群体的问题。

`lib/material-facts-v2.ts`、`lib/material-facts-v3.ts` 与已封存实验/训练资产未修改。生产 snapshot、poll ingest、response 已有的 source-review 边界执行新守护。原始模型回答、representation、value、quote、Unicode位置和人工确认均不重写，不升级原本不可解析的金额。

## 剩余边界与合并条件

这是保守的运行期可用性检查，不是通用中文事件理解或法律专家判断。复杂跨句/多行、罕见含连接字姓名、无法消歧的上下文会减少自动提示，必须保留人工核对。外币守护不做汇率换算，沿用项目对¥/￥的人民币兼容约定；不把该符号单独视为全世界语境下的币种证明。此前已经人工确认的金额不会自动撤销或改写，历史人工判断仍需要对照原文负责。

P2依赖后续本人案件请求重试、每次最多处理5项并遇首错停止，不是后台自动清扫。真实材料业务验收、用户界面验收和生产环境验收均未在本轮发生。未改变前端交互，未把既有截图作为本次浏览器验收。

技术上四类已复现P1及本轮同类扩展可关闭；完整CI成功和审查处理完成后，可按依赖顺序推进合并。PR #40 当前base为 `feature/material-fact-chain`，依赖仍打开的 PR #36；应先完成依赖合并，再同步base并确认最终目标上的检查。未经另外授权不合并或部署。

本轮3位子Agent分别负责币种实现、取消机制动态核查/回归脚本、独立对抗验收；主Agent负责源文关系/完整性实现与整合。均显式请求子Agent `gpt-6.1-sol` / `ultra`，此为委派工具可见配置，未独立核验主/子Agent服务端实际路由。
