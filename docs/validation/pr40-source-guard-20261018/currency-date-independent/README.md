# PR40 币种与日期事件独立验收

基线为 `2d37c6b9e6258153099476313dc4c634bf9994c8`。本代理仅新增三个测试文件，产品实现由主代理及另一代理完成；复验时把其最终三个产品文件复制到独立工作树。产品及测试 SHA256、计数和边界见 `report.json`。

两批共 79 项独立测试先在原版动态执行：29 通过、50 失败；最终日期 helper `6266aa769459619181aeba3cda262efdf8912f8a94a0edc3bccea2254fe4a181` 与币种修复整合后，79 项全部通过。另实际运行既有币种 114 项、来源审查 72 项、运行时去重独立测试 50 项，共 236 项全部通过。不能用这些绿测试替代自然语言、真实模型、浏览器或人工验收。

基线复现的主要业务错误：

- 裸数 `8000` 在 due、paid、rate、other 四角色中被解释为人民币精确金额；人民币单位仅出现在表头、其他文本块、其他劳动者事件或逗号/换行后，也无法让当前裸数具有币种证据。
- 收款日期被错标为任职、工资归属、签约、履约或其他日期时，原版没有归属核对提示。六种明确事件与六种模型角色交叉后，30 个错标签中 25 个缺失提示；其余 5 个被原有 payment_date 收款者守护阻断。
- 额外旁路复现裸 `0.00`、`8000.00`、`0.8万`、`8,000`；相同标签的裸数与带元观察可在四种顺序/引文大小组合中互相挤掉；`JP¥8000` 裁去 `JP`、但保留 `¥8000` 时也能错当人民币。

修复后，79 项确认了这些输入降低派生可用性，原始 value、quote、meaning、raw 和源位置仍保留。人民币直接附着的元、人民币前后缀、¥/￥、RMB/CNY 正向例，以及六种明确匹配的日期角色仍通过。新金额守护没有改动冻结 v2/v3 解析契约；测试明确保留冻结解析器将裸数解析为数字的旧行为，再要求运行时来源审查将其降为不可用。

最终币种 helper 更新为 SHA256 `73f8aea84dee183f1b8ee02b21fb7babb1b973d8ac02533470d57f89088c52fb`：仅比较副本折叠 NFKC、去除 Cf 格式控制字符且不跨换行，并排除元旦、元宵、元年等明确非币种词的单位边界。在这份最终产品上重新执行原 79 项独立测试及 236 项相邻回归，315 项全部通过。两份原版基线 JSON 及三个独立测试文件保持原样，基线哈希另录于 `report.json`。

两项 D1 回归使用真实临时 Miniflare D1、真实 facts GET/POST 路由及生产 store。只有材料服务的合成输出受控，没有启动 Worker、调用真实模型或部署。裸数用例完成 extract → poll ingest → source review → reload → 手动范围确认 → 再读取：四阶段金额均不可用，范围确认不能解除限制。独立手动输入应付 9000、已付 0 仍实际完成计算、差额 9000，原始模型裸数 8000 持久保留。日期错标提示也在提取、重读及范围确认后保留。每项运行均由 finally 钩子销毁临时 D1 运行时；未留下服务进程。

验收范围是有限明确语法与同一源文局部币种、事件角色关系。在这些边界内未发现剩余可复现阻塞；没有保证全部自然语言都能自动理解。表头币种和跨行单位保守要求人工核对。完整 CI、合并后实际浏览器和用户人工验收仍由各自证据单独证明。
