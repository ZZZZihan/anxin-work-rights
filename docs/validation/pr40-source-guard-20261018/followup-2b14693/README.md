## 问题、修复与可达性

1. **所有角色均须核对归属。** 原守护只拦完整个人总额；rate、payment、arrears、award、other_money、非完整总额和各类日期仍可借别处主体或期间。现在所有结构化候选都有源文关联检查；含复杂转述或不能绑定同一事件时追加 `source_relation_unresolved`，原始标注仍保留供人工核对。
2. **回指当前金额的另一事件不能被忽略。** `另一工人的工资也计入上述总额`、`另一班组…包含上述总额`、`李乙…9000元也计入上述总额` 都会阻断个人总额；只有有限语法明确支持的独立事件可以略过，未知尾句不能消失。
3. **付款者不自动成为受益者。** 源文“支付/付款/给付”不等于“收到/领取”。检查依据源文方向词，换成费率、欠款或日期等模型标签不能绕过。明确收到与裁决应得的正向归属仍保留。
4. **推进阶段显示取消仍未完成。** `processingCleanupPending=true` 时同一条通知保留阶段保存成功结果并追加后台提取尚未确认停止；普通成功、完成阶段、失败不推进和重试恢复均单独验证。
5. **旧v2非空提取也显示疑似漏提。** 服务端在同 evidence id/SHA/revision 的已就绪原文上生成 `sourceCoverage`，Panel读取派生诊断。来源失效时清除旧派生值；普通保存和计算直写均剥离该字段，历史schema、raw及原coverage不迁移，不补写候选或金额。

## 残余边界

有限语法优先防止错误归属，可能让合法的复杂跨句、表格、省略、罕见姓名或方向不明表述也要求人工核对。它不是任意自然语言的完备解析器，也不能证明文书真实性或法律上的完整应付。以前已经人工确认的金额不会被自动撤销，历史人工判断仍需对照原文核查。

覆盖诊断是启发式提示，不能证明材料没有遗漏；它不会生成新事实。取消队列重试依赖后续本人案件请求，每次最多5项并在首次失败时停止，未新增后台清扫。

本轮仍未运行新模型推理、训练或真实材料业务/法律专家验收，未操作生产。浏览器技术检查也不等于用户人工验收。PR仍按#36依赖顺序推进，最终CI与新一轮审查状态见PR；未授权合并或部署。
