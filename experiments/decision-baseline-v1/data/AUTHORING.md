# 安薪乐业 decision-baseline-v1 合成样本说明

本目录交付108条由 Agent 按任务约束逐条编写的合成输入及其独立标签。全部标记 `synthetic: true`、`provenance: agent_authored_synthetic`。它们不是当事人的材料、真实案件、判决摘录或经人工业务验收的劳动争议结论；编写过程中没有检索或复制真实裁判材料，也没有额外运行被测模型、调用业务付费API或启动训练。编写 Agent 自身属于语言模型，不能将这些数据称为人工专家标注。

依据为上层 `CONTRACT.md`。任务只判断当前一步需要补什么信息、是否有未协调的冲突、能否调用工资差额算术工具，或者工具达到重试上限后应否报告失败。期间工资总额必须有明确确认，月薪、日薪、时薪、计件单价、月份和出勤天数均不自动替代该总额。零值可用；未知不作零。非工资款不进入工资实付。

每组两条对照，组不跨划分。72条test属于36个合成场景组，不可当成72个独立真实世界样本。每个输入只包含 `id`、`messages`、`tool_state`；标签另存划分、组、类别、出处、预期输出及理由。ID使用与答案无关的稳定散列，未把动作或缺项编码在ID中。推理时应按合同仅发送消息和工具状态，不能发送标签、理由、类别、组或本说明。train不是已经获准用于训练的数据，本次仅供基线规则和格式开发；任何训练均未执行。

类别是场景的主要观察点；完整多轮或已拆分报销样本也可能调用工具，因此类别不与动作一一对应。dev没有单列missing_period样本，但包含期间冲突及其明确更正；主要期间缺失覆盖在train和test。类别没有强行等量，避免为了数量重复同一情境。

编写覆盖了：完整期间缺失、仅有起日/止日、月份无年份、旧期间不能挪用于当前结算、跨年和有效闰日边界；月薪不等于期间总额，以及日费率、时费率、计件标准仍待结算确认；转账属于旧期间或私人借款的歧义、工资付款清单尚未查全、拟付款不等于实付；报销包含于总款、报销另付和包含关系未知；不同来源未协调的冲突、用户明确作废旧值的纠正；多轮补齐后只询问剩余字段；明确零值、分币小数、全部工资分笔相加、负算术差额；工具连续两次超时，包括失败状态与缺项/冲突并存的情形。

对照样本改变的是信息是否明确、归属是否确定、付款清单是否完整、冲突是否得到明确解决等可观察条件。职业背景、表达方式、轮次数量和日期边界有变化；没有用单一段落模板替换名字和金额来补足72条test。标签仅依据该条输入内已经出现的事实，不借用同组另一条输入或之后才会得到的事实。工具参数中的分笔实付合计只在输入明确列出本期间全部工资付款时相加。

`build_dataset.py`保留手写样本的可重建源；`validate_dataset.py`执行结构和算术检查，`validation.json`记录结果、六个JSONL的SHA-256及49次金标工具差额回放。已实际运行并通过：108条输入与标签ID逐条对应、ID唯一、完整会话无重复、严格字段结构、54组不跨划分、每组两条、test不少于30组、提问字段恰好覆盖缺失与冲突且不重复、缺失与冲突不重叠、所有调用日期可解析且起日不晚于止日、金额有限且最多两位小数、工具两次超时对应失败动作。金标调用中有9个显式零金额参数、3条负差额。

编写者还逐条按可见消息核对了日期、金额、归属、总额完整性和显式纠正；这是编写者自查，不能替代独立复核。自动校验能够验证结构和给定参数的算术，不能证明语义金标正确。其余歧义均被有意标注为缺失或冲突；当前未识别到需要私自补充隐藏事实才能判定的样本。独立复核及三条基线的实际表现由主任务另行执行和记录。

test及包含test源的 `build_dataset.py` 只交给冻结后的运行器和审查方，未发送给规则实现Agent。共享文件系统本身不能提供强访问隔离，主任务应继续限制规则实现Agent只读train/dev四个JSONL；基线冻结之后不得根据test结果修改规则或提示词。test的语义组来自同一编写者且使用同一任务合同，这种留出方式比真实外部数据更窄，不能代表跨来源泛化、实时多轮补全、OCR、RAG、法律正确性或生产可用性。
