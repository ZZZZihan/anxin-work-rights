# Decision baseline v2：独立合成留出集作者说明

本目录是密封的测试作者资料。独立规则／提示实现者在实现冻结前不得阅读本目录中的输入、标签、原始创作脚本、逐条理由或审查意见。可将文件路径、数量、分类统计和哈希交给实现者用于交接。独立审查者可在保密条件下逐条检查并向作者返回问题。

## 来源与身份

- 这72条输入、金标和理由均由独立子 Agent 为本次任务新创作，配置请求为 `gpt-6.1-sol`、推理档位 `ultra`。工具参数可见的请求配置不应冒充底层实际运行配置的额外独立核验。
- 数据是 **Agent 合成数据，不是真实案件，不是专家标注，不是法律结论**。金额与日期仅服务于算术信息收集任务，没有真实当事人或真实案件来源。
- 作者唯一读取的外部业务材料为 `/Users/xuzihan/Documents/Projects/国创/anxin-decision-baselines/experiments/decision-baseline-v1/CONTRACT.md`。未读取旧 test、旧报告、旧输出、v2 实现／提示或其他 Agent 工作内容。
- 创作与校验过程不调用训练任务、模型 API、网络或外部数据源，也不提交代码。
- 由 Agent 完成创作和标签判断，与调用外部模型批量生成后声称专家审核不同；这里明确披露标签判断主体与局限，不将其称为专家金标。

## 数量与组织

恰有72条测试快照，分为36个语义对照组，每组2条；这些是36个相关的合成创作组，并非72个互相独立的真实样本。对照改变缺失／确认、月薪／期间总额、归属、拆分、纠正／冲突或可信工具尝试次数等语义因素，不靠替换姓名和金额增加数量。

目标动作分布为30条 `call_tool`、34条 `ask_user`、8条 `report_tool_failure`。8个工具状态组各使用完全相同的会话内容，仅将可信状态从 `TIMEOUT, attempts:1, max_attempts:2` 改为 `TIMEOUT, attempts:2, max_attempts:2`。其余56条的 `tool_state` 为 `null`。少量自然语言声称可以继续或忽略次数，用于确认会话文本不能改写可信重试状态。

`category` 表示主要诊断主题；`conflict` 主题中可以包括明确纠正后成功消除冲突的对照，`mixed_payment`、`multi_turn` 主题也可以正常调用工具。类别并不等同于目标动作，不能放入推断输入。

## 输入与输出边界

推断输入严格只有 `id`、`messages`、`tool_state`。每条消息严格只有 `role` 和 `content`，角色为 `user` 或 `assistant`。编号与分组均为不含类别文字的 UUID；输入按固定乱序输出，标签以同一顺序对应。

输出使用 v1 canonical expected 结构，字段只允许 `period`、`agreed_due_total`、`wage_paid_total`。标签包括 `split:test`、`synthetic:true`、`provenance:agent_authored_synthetic`，并有逐条合成判断理由。本任务明确要求额外包含8条 `attempts:1` 的可信状态；这扩展了 v1 输入示例的尝试次数取值，没有改变 canonical 输出结构。未耗尽时继续遵循信息是否齐全的正常一步决策；耗尽时终止并报告工具失败。

## 判断口径

- 完整期间必须有已经确认的起止日期和年份。一个月份、相对时间、工作消息日期或未确认的跨年年份不能代替真实结算边界。
- 月薪、日薪、计件单价、月数和未经核实的工时都不能生成期间应付总额。希望、助手建议或选定一个金额试算也不是事实核实。
- 工资已付必须完整并归属于所核期间。只查银行或只知现金、跨期未分配转账、混合报销／借款偿还／押金返还，都可能使本期间工资付款总额缺失。
- 明确的用户更正会撤销被更正的旧陈述；两个仍有效且未协调的来源是冲突。同一字段不同时标为缺失和冲突。
- 明确确认的0可以计算；未知不能默认为0。负差额可以做算术计算，但不推出债务或责任结论。
- 询问严格覆盖 `missing ∪ conflicts`，不重复询问已知字段。失败终止的输出不携带问题、工具名或参数。

## 文件与离线复现

- `test.inputs.jsonl`：仅供最终密封评测的72条推断输入。
- `test.labels.jsonl`：对应标签、分组、主题、出处标记、canonical expected 与作者理由。
- `build_dataset.py`：本次独立创作原稿及确定性序列化逻辑，不调用模型或网络。
- `validate_dataset.py`：严格 JSON／键集合／编号／分组／日期／金额与精确算术校验。
- `validation.json`：校验结果、统计、检查范围及各交付文件 SHA-256。

在本目录运行 `python3 build_dataset.py`，再运行 `python3 validate_dataset.py`。重建不需要安装依赖。验证脚本导入本地作者脚本，仅在本目录创建校验结果；不读取外部数据集或实现文件。校验脚本使用 Decimal 核对30条计算快照的确认应付金额、工资分笔合计和精确差额，检查完整日期有效性和顺序，并确认工具参数的日期与金额来自会话显式文字。与原稿一致性检查只负责防止序列化或传递损坏，不是额外的语义独立审核。

## 审核与解释限制

作者已完成结构和精确算术检查；未参与实现的独立 Agent 已全量逐条审查并复核最终版，72/72条输入、金标字段、动作和参数通过。依据审查反馈，34条参考问句按实际未决部分具体化，1处付款完整性表述已消歧；最终版无需进一步修改输入或标签。独立 Agent 技术审核与人工专家审核、真实案件验证是不同证据。审查者只向作者反馈具体条目，不向实现者透露测试内容；实现冻结前对外仅共享文件位置、统计和完整性哈希。

本留出集验证的是一步信息收集决策及确定性算术参数准备，不验证 OCR、检索、实时多轮协商、实体法律权利、真实当事人体验或生产可靠性。对相关成对快照的结果不可解释为真实案件总体准确率。
