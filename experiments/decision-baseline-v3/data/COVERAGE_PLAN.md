# v3 新留出集覆盖计划（尚未编写正式样本）

## 范围与边界

- 目标：判断某段工资期间的可信事实记录是否足以进行确定性算术，进而追问、调用计算工具或处理工具失败；不评价法律结论、真实欠薪认定或完整生产流程。
- 建议规模：72 条、36 个语义对照组，每组 2 条。各组只改变一个会影响决策的事实条件；自然语言、事件顺序、数值和时间组合独立新写。
- 全部情境及可信事实输入均为作者构造的合成资料。所谓“已确认”仅指情境内模拟用户确认记录；不表示真实用户确认、材料核验或专家标注。
- 新输入必须携带独立于模型的结构化可信事件或事实记录，供系统公开消费。这些记录属于输入事实，不是隐藏金标；期望动作及评分标准另存。
- 当前仅规划覆盖，不提供正式样本、具体金额、具体日期、gold、模型预期输出或可反推出正式样本的成对文本。
- 等待主 Agent 提供稳定的 v3 可信事实输入合同后再写正式内容。不读取新实现、提示词、模型输出或旧 test、results、review、REPORT；不调用 API、模型或训练，不提交 Git。

## 次级交叉与成对原则

1. 同时覆盖可计算、仍须追问、事实冲突和可信工具不可用等分支，最终数量随稳定合同预注册，不根据实现表现调节。
2. 每组仅改变一个业务条件；相同数字可以具有不同的范围、状态或来源，避免仅凭“金额出现过”决定可计算。
3. 每个主覆盖族至少包含一种自然语言误导：口语省略、承认不确定、后续纠正、引用旧话、摘要概括或不同记录粒度。误导必须能由公开可信事实输入明确解开。
4. 同时覆盖事实内容正确但尚未确认、明确确认而值为零、已确认后失效、可见话语声称确认但可信记录缺失等状态；不把自然语言措辞当成可信通道。
5. 金标不依据模型实现推导。若合同无法决定某个案例的唯一合法动作，应先请合同方澄清或将案例留在候选区，不为凑足数量作隐含规定。
6. 最终成对样本、组信息和 gold 的访问保持分离：实现方冻结前只接收本覆盖计划；历史集排重交由另一审查者完成。

## 稳定合同至少需要明确的项目

- 可信输入封套：谁写入、什么字段属于可信内容、自然会话与可信记录冲突时的优先关系。
- 状态词表与字段粒度：确认、未知、待确认、撤回、冲突、取代等允许状态及其含义；是否支持按“字段＋工资期间＋金额归属”定位。
- 事件生命周期：记录 ID、事件 ID、取代/撤回目标、时间或顺序的用途、重复事件的去重规则；不能默认为最后写入覆盖。
- 数额语义：月薪/期间总额、金额单位、字符串或数值规范、最大小数位、零/缺省/null 的区别、负值与四舍五入约定。
- 付款归属：工资期间、工资与其他款项分类、分摊确认、重复单据、总额与分项能否合并。
- 决策边界：必需事实、追问字段、冲突优先级、允许计算条件、工具参数、工具结果可信来源和失败动作。
- 状态上限：可使用的用户可见状态与禁止升级的结论；不能把模拟确认或算术结果说成真实欠薪认定。
- 测试输入与 gold 的字段清单及分离规则；来源/状态说明应记录在哪个独立文件。
