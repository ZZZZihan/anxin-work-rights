# v3 稳定合同独立审查

日期：2026-10-17。仅审 `experiments/decision-baseline-v3/CONTRACT.md`；未读实现、提示词或任何新留出内容。与标签审查、后续技术审查分别记录。

结论：未发现使方案无法实现的业务矛盾。unknown 与确认 0、合法负差额、当前期间绑定、程序状态上限、模型提案与系统结果的区别均已写清。以下口径建议在实现/指标冻结前明确。

1. **确认引用的证明强度。** 现文允许 confirmed 只需至少一个 confirmation 源，而字段实际数字可仅在另一个 evidence 引用中出现。模拟受控事件本身可以授予确认状态，但“引用存在”不能进一步被宣传为“引用证明已确认该金额”。可选择要求确认引用直接支持当前值，或明确确认权来自受控事件、引用检查仅证明字面出处；二者应选定，不能混用。
2. **字面值匹配。** 日期/金额应是独立字面 token，不能以子串命中作为支持。尤其金额 0 不能通过任意日期或其他金额中的字符 0 获取出处。源文本与金额字符串的等值格式（如小数尾零）如何处理也需固定，不能按新题失败临时修改。
3. **原始文字与事实表优先级。** 需要明说这轮的可执行事实以程序 ledger 为准，messages 内新增、自称确认或撤销的文字只属未进入受控接口的消息，不直接改变 ledger。否则作者、模型和评分者可能分别按自然语言与结构化状态判定下一步。真实生产把消息转成候选/确认另属未来集成。
4. **危险调用分母。** “危险实际执行”计实际工具调用是否发生，不能只计工具返回成功。缺事实/不匹配提案调用工具后即使异常，也属于闸门未阻止执行。危险事实与参数不匹配可分别报告。
5. **拒绝与追问刷分。** 条件为事实充分且 proposal 参数正确的 gate 放行率，与所有事实充分场景的模型正确调用/系统真实成功率分别报告；模型全追问可能不会引起 gate 误拒绝，却仍不能完成任务。危险 proposal 为 0 时阻断率应报告“不适用/0分母”，不能记100%。
6. **并发主张要对应实现。** “本地锁保护核对到执行的原子边界”应由同一可信 ledger 的修改、核对和调用共享的锁与独立并发反例验证支撑。只给 guard 自己加锁而外部 ledger 可另行修改，不支持此主张。生产分布式/持久化保证仍不在范围。
7. **同提案复演的解释。** 模型看到结构化快照后得到的下一步表现，不包含自然语言事实抽取准确性。两臂复演隔离 gate 的增量；对于没有模型危险输出的情况，另列人工恶意提案回归，明确这部分是组件覆盖而非模型成绩。

以上只涉及公开设计边界和预声明口径，不包含任何新测试题、数值或标签。
