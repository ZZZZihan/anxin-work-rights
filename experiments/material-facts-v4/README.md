# 公开材料到用户确认：v4 实现与实测

2026-10-17。材料候选、原文定位、用户核算范围、完整总额确认、冲突说明、撤回和计算已接入网站及 D1。**候选始终不具有计算权限，未知金额保持未知，明确输入并核实的0元合法。** 本轮没有训练、LoRA或生产部署，v1-v3字节不改。本分支依赖PR #31，跟踪Issue #35。

这轮已能定位问题，但**没有得到足以给Qwen和DeepSeek排名的完整留出结果**：Qwen受本机内存压力限制；DeepSeek两轮均受网络错误中断。运行失败与已返回回答中的语义错误分别保留，不能从多个运行挑成功答案拼表。

## 接通的业务行为

- 每份材料保留原文件摘要、分析版本、原文块、程序计算的Unicode位置、原回答及被拒候选。输出多余授权字段、改写引用或格式不合要求，不自动纠正成事实。
- 月薪、单笔付款、欠款主张、命令支付额与完整应付/已付总额分别表示。用户确认劳动者、用人单位、工资期间，逐项核对候选并说明金额口径/冲突取舍后，才能确认完整总额。
- 只在当前材料全部提取或明确排除、范围和两项总额均确认后，服务端同一D1条件写入以整数分计算差额并记录回执。新上传、来源修订/删除、重新提取、范围变更、撤回、归档或并发版本冲突会阻止沿用旧授权。
- 默认规则模式；维护者可配置Qwen或DeepSeek。两者共用同一候选内核与Python推理入口，固定后端、任务排队、取消、超时和内存保护均在服务端执行。DeepSeek模式明确提示会发送材料文字。

完整合同见 [CONTRACT.md](../../docs/material-facts/CONTRACT.md)，本机启动配置见[材料说明](../../docs/material-demo.md)。用户核实说明是自述依据，不等于程序证明材料真实或账目完整。当前确认保留依据，历史仅有500条有界动作元数据，材料删除会清除该案件事实缓存；这不是永久法律证据账本。

## 数据与独立性

使用12份官方公开行政文书的必要脱敏摘录：开发3份/40项候选、留出9份/167项候选，按案件及关联工程分组，案件族重叠0。原HTML仅本机留存，证件/地址/电话等不必要标识经过排除或脱敏；必要公开当事人名称仍可能存在，不称完全匿名或开放训练数据。

材料作者未读实现、模型提示、旧题或模型输出。金标经过另一Agent逐条复核；主实现者在[冻结清单](freeze.json)生成前没有读留出内容。输入从首次交接起字节不变，标签在推理前按来源复核修订，40/167最终版本和所有备选均封存于[data/freeze.authoring.json](data/freeze.authoring.json)。`provisional`仅为保留的旧文件名，以冻版哈希确定最终字节。

这是**真实公开文书的文字测试**，不是工资条/银行流水/聊天原件，也没有验证扫描OCR能力。同机构模板可能跨集，公开文书是否已进入模型预训练未知；独立标注复核不等于法律专家或用户验收。权限、来源与复核范围见[data/README.authoring.md](data/README.authoring.md)。

## 留出运行结果

全部行以同一9份、167项金标为计划分母。基础匹配为候选类型+规范值；严格匹配再要求主体、期间、金额口径和断言身份全部正确，且引用通过同一应用校验。

| 运行 | 完整回答/计划 | 基础 TP / FP / FN | 严格 TP / FP / FN | 严格F1 | 实际限制 |
|---|---:|---:|---:|---:|---|
| 规则首轮 | 9/9 | 5 / 1 / 162 | 0 / 6 / 167 | 0 | 仅匹配少量明确金额词，无法解释主体/期间/主张身份 |
| Qwen3-32B-4bit首轮 | 0/9 | 0 / 0 / 167 | 0 / 0 / 167 | 0* | 第一份生成约16.1秒时触发外部内存保护，其余未运行 |
| DeepSeek-v4-pro首轮 | 1/9 | 8 / 9 / 159 | 5 / 12 / 162 | 5.43% | 4次请求，3次网络错误，达到停止条件 |
| DeepSeek独立补充轮 | 2/9 | 19 / 3 / 148 | 4 / 18 / 163 | 4.23% | 从第一题重新开始，5次请求，3次网络错误，未拼接首轮 |

\* Qwen的0是“全计划任务没有可接受输出”的交付分数，**不能解释成模型语义能力为0**。DeepSeek低召回包含大量未完成/未访问输入，不能当成纯模型正确率。没有一份已完成文书严格全对；本次没有测得可用于模型排名的完整配对结果。

原始回答、请求次数、结束原因、内存遥测、输入消息、代码哈希和逐条评分都在[results/](results/)。DeepSeek未启用thinking，温度0，每份最多4096输出token，无自动重试。预先规定累计3次网络错误停止；实际账单未知，保留预算上界不当作实际费用。

Qwen使用本机既有原始4bit模型，无适配器。开发阶段保留三轮资源诊断：首轮FP16 KV、第二轮4bit KV均完成第一份后停止；第三轮改为每材料独立进程仍触发保护。正式留出采用独立进程、4bit KV、24GiB allocation/20GiB wired、512MiB cache、prefill128，首次进程失败即停止整批。没有关闭用户其他应用，也没有放宽保护阈值。三轮开发结果不混入留出分数。

## 问题主要在哪

1. **运行稳定性先限制可比较性。** 64GB统一内存并未保证当前多应用环境下32B能稳定完成这批文书；本轮记录证明的是当前配置/负载下中断，不能推断所有64GB机器都不能运行。DeepSeek的网络请求错误也不能归因于推理能力。
2. **结构化输出仍是独立门槛。** 两次开发Qwen完整回答都包了Markdown代码围栏，违反纯JSON协议；另有引用改字。离线剥围栏可帮助诊断，但没有用于正式评分，也没有作为应用自动修复。
3. **数字提取正确仍可能业务含义错误。** DeepSeek曾把项目经理标为劳动者、把工作地点标为期间；补充轮把11人的集体工资金额归到单个劳动者。Qwen还把“未按时足额支付”的欠付金额标作完整应付。引用合法只能证明文字出现，不能证明这些关系正确。
4. **确认链路能挡住未授权计算，不能代替语义理解。** 候选不自动填进总额，用户必须核对完整范围和金额口径；确认之后仍保留冲突候选。真实材料缺少支付全貌时，正确结果可以是继续补材料，而不是算出一个金额。

详细证据由未参与相应回答生成的Agent核对，见[FAILURE_REVIEW.md](FAILURE_REVIEW.md)。下一步优先在稳定运行条件下完成同题对比，再针对严格JSON、引用保真、集体与个人归属、主张与决定分别改进；当前证据不支持马上启动LoRA或RL。

## 复现边界

`node experiments/material-facts-v4/verify.mjs` 校验数据/代码/运行原始记录的哈希，并仅从已保存回答重算成绩，不加载模型、不访问API。CI运行该命令和新事实链隔离HTTP回归。模型重跑必须使用新的输出目录，不能覆盖本轮；参数与计分规则见[METRICS.md](METRICS.md)。

留出运行完成后，技术复核发现运行器日志写入/JSON事件解析失败可能造成未处理Promise拒绝。另外复现了stdout分块解码损坏中文的问题。冻版文件只修订运行器错误清理、分块解码与验证入口，网站侧服务同步修复解码，原冻版源码另存，修改前后哈希与时间见[freeze-amendment-1.json](freeze-amendment-1.json)。数据、提示、内核、推理脚本和评分器未改；没有据此冒称重跑模型或调整成绩。最终检查边界见[FINAL_INTEGRATION_REVIEW.md](../../docs/material-facts/FINAL_INTEGRATION_REVIEW.md)。
