# v4 真实公开文书摘录与独立标注工作包

本目录保存 12 份政府公开的行政处理/行政复议文书文本摘录，开发集 3 份、留出集 9 份，按案件/关联工程分组。输入没有人工金标、人工确认或核算授权；标签单独保存。金标由作者独立编写、完成字面与定位自查；另由未参与材料/金标编写的 Agent 逐条语义复核。**当前复核状态以与四份数据文件哈希一致的 `*.independent-review.json` 和 `validation-report.json` 为准**；provisional 文件名不自动代表已经冻结或已经人工确认。

## 文件及隔离边界

- `dev.inputs.jsonl` / `dev.labels.provisional.jsonl`：可供主 Agent 开发与独立审查。
- `holdout.inputs.jsonl` / `holdout.labels.provisional.jsonl`：主 Agent 在实现、提示词、评分规则冻结前不读；由未参与相应实现的审查 Agent 复核。
- 两个 split 的 `*.gold-locators.jsonl`：按 `id + expected_index` 给出 quote/value 在 block 中的 Unicode 码点位置；区间为左闭右开。
- 两个 split 的 `*.excerpt-receipts.jsonl`：从原网页 selector、原段落序号到受控摘录的回执，含脱敏前后哈希、脱敏位置和原因。
- `sources.selected.json`：选入 12 份来源的机构、发布日期、网址、获取方式、原始网页及摘录哈希和分层权限说明。主 Agent 可读来源元数据；其中没有金标内容。
- `source_catalog.provisional.json` / `SOURCE_REVIEW.md`：先行来源审查，记录 16 个可获取页面、关联案件排除及备选，不等同全部进入评测。
- `validation-report.json`：静态数据、原文重建、哈希、定位、枚举和分组检查结果及数据文件 SHA256。计数不代表语义正确率。
- `collect_public_sources.py`：公开网页获取脚本，不登录、不调用模型。
- `author_materials.py`：开发集人工选段/标注定义和共用数据编排函数，仅本机作者配方，已忽略；其中脱敏映射含移除前字面，不进入 API/Git。
- `author_holdout.py`：留出集人工选段/标注定义，仅本机作者配方，已忽略；主 Agent 冻结前不读。
- `validate_authoring.py`：离线校验脚本，独立于模型及应用实现；不会调用模型、训练或运行应用测试。
- `raw/`、`clean/`：原始 HTML 与未筛查全文，仅本机留档，已列入 `.gitignore`，不可直接当 API 输入或加入 Git。
- `versions/`：首版及独立复核历史的按字节快照，仅本机留档并忽略；其中作者配方可能包含移除前标识字面。

所有操作只写本 authoring 目录，未修改应用仓库、未提交、未访问密钥、未调用 Qwen/DeepSeek 或其他模型、未训练。标注者仅阅读冻结合同与 RawCandidate 类型，未阅读应用实现/提示词、旧测试题或旧成绩。

## 原文与摘录的真实性

材料来自实际可免费访问的政府公开网页，保留原始响应 HTML 字节；不是工资条、银行流水截图或这些证据的原件。文书引用的工资表、银行流水、微信、欠条等，只在文书叙述中出现。荣昌页虽嵌有工资明细附件，整个附件均未作为 API 输入或金标来源。

摘录选取网页文章正文中完整、有边界的原段落。没有把多个来源拼成同一份“真实材料”，没有重绘票据、补造金额、填充日期或把缺失金额改成零。为保护不必要身份信息，个别原段落作明确占位脱敏；回执可从本机原始网页重建前后变化。HTML 为逻辑第 1 页，页码不声称原打印页码。

HTML 展示文本的规范化仅为：按原顺序连接内联文字节点、不插入跨节点空格，将现有连续空白压为一个普通空格并去首尾空白。不改中文标点、数字或单位。选段没有截断句子。荣昌与横栏两篇短材料自然不足 1000 码点，没有以无关法律说理凑长度；其余摘录均在约 1800–4000 码点内。每份不超过 24000 码点、40 个候选。

`source.sha256` 的固定定义是：按 blocks 顺序，以两个 LF 字节连接各 `block.text` 后，对 UTF-8 字节取 SHA256。它是**摘录哈希**，不是原页哈希。原始 HTML 字节哈希另记在来源元数据和回执中。不同原始网页即便内容相近，也不依此视为独立案件；划分以 `family_id` 为准。

## 标注口径

金标按冻结合同的严格八字段 `RawCandidate` 编写；所有字段仍是候选。作者未确认工资应付/已付总额，也未授予任何计算执行权。

- 主体：`worker` 只标文本明确涉及的劳动者，法定代表人、代理人、工头、承包人不因姓名出现就成为劳动者。`employer` 是文本有对应用工/工资责任语境的候选实体，仍不代表已经确认劳动关系；只有处理对象、证据标题或资金过路公司的，不据此强行推断用人单位。`subject` 是本条对应劳动者的原文名称；集体金额不绑到列名的第一个人。
- 期间：工资、任职、签约以及其他相关期间分别处理；保留“左右”、缺年/月/日、边界日期等原文字面，不能填满。金额的 `period` 只在原文能明确对应时填写。期间可以是明确边界或原文连续表达，不能为凑标准日期拼接相隔的字符串。
- 金额：月薪、完整期间应付、完整期间已付、欠付、命令支付、单笔/一批付款和其他金额分别处理。`partial` 表明组件、部分款或局部付款口径；它不证明完整总额。日工资及餐补等单位费率用 `other_amount + unknown`，不改成 `monthly_rate`；`partial` 只用于明确组件累计额、部分款等金额，费率本身不因此成为部分金额。罚款、工程款不当工资总额。正文公开“完整月应发+实到”也必须分别保留 gross/net，不能直接执行相减。
- 断言：明确请求、陈述、抗辩、投诉或嵌套当事人说明是 `claimed`；只有“确认/认可/承认”等明确承认具体事实，才用 `admitted`。行政/司法命令金额是 `award`，相应历史决定事件用 `decided`；后来被撤销的决定仍是历史文书事件，不成为当前有效的确认工资债务。证据名册/工资表标题的客观转述可为 `narrated`，不自动成为裁判事实。
- 同一事实按 `kind/value/subject/period/qualifier/assertion` 可观测语义元组去重；同事件跨段或不同发言者同义复述且上述属性不变，只列一个 expected 并给精确引文备选。不同来源主张、明确承认、处理命令或后来审查认定，只有可观测属性实际不同时独立列项。现有八字段没有 claimant/payer/event，不能靠隐藏标签要求输出不可区分的重复项，也不能以最后认定覆盖不同属性的主张。
- 实体别名是同一身份候选的字面备选，不制造多个雇主；每个备选的 assertion 仍按其精确 quote 的自身语境填写，不能靠另一处“经查”标题升级嵌套主张。
- `worker.subject=value` 与 `period.period=null` 是默认编写形式；合同原未明示，故逐项预登记 worker.subject=null/self 和 period.period=null/self 备选。金额的已知主体、期间不因此放宽为 null。
- 工资表或流水只被提及，不推定标注者已经取得该原始证据。欠款不能倒推出应付或已付总额；月薪不能乘月份补总额；没有数字不是零。

`acceptable_alternatives` 在作者未读取任何模型回答时登记，并在首次留出推理前冻结，结构为 `{expected_index, candidates:[RawCandidate], reason}`。用来登记同一事实可接受的精确字面别名、原文数字/中文金额等价，以及重复叙述的支持位置/断言。它不是“看到模型结果后再补正确答案”的入口。评分仍应对重复输出作最大一对一匹配，不能以多个重复候选刷召回。

当前 `kind` 不需要再增加：日费率、罚款、工程款可归 `other_amount`；不确定主体用 null，不额外造 `payer`/`daily_rate`。需要审查者重点把握的是自然人承担支付责任与“用人单位”的边界、当事人自述“确认”与明确承认的区别，以及历史被撤销命令的断言时间语境。现有五个 assertion 可保留；缩并会掩盖本轮要检验的来源差异。

## 隐私与使用权限

公开可读不构成开放许可。来源页未发现明确开放数据/训练许可；部分站点底部条款链接的正文在获取时超时，未把“未读到禁止”写成“已经获准”。本轮只作用户授权的小批、非训练推理评测，不声称拥有训练、批量采集、再分发整页或通用第三方处理许可。

已逐段筛查并排除或明确脱敏：个人证件字段、社会信用代码、出生年月/性别等不必要身份描述、住所、具体住宅施工门牌、联系电话、邮件追踪编号，以及包含证件列的完整工资附件。API 只应读取 `*.inputs.jsonl` 的受控文本，不读取 raw/clean、标签、定位回执或任何私密附件。为正确评测主体归属，文书原有当事人名称（含官方匿名写法及必要实名）保留；这不是将数据宣称为完全匿名。

分层记录如下：免费无登录读取已实际观察；内部小批评测为本任务用途；第三方 API 仅可使用经筛查短摘录，未观察到文章页明确禁止第三方处理，但完整站点条款尚未全部核清；整页再分发未获明确许可，原文仅本机留存；训练未获授权、未计划、未执行。来源若后续发现明确禁止第三方处理，应在首次推理前排除该来源并记录理由，不绕过限制。

Git 交付只应考虑必要短摘录、元数据、获取/校验脚本和定位说明。原始 HTML、未筛查全文、本机缓存、含移除前字面的作者配方及版本历史留在忽略目录；本 Agent 不执行 Git 提交。必要短摘录同样不被包装成开放许可证数据集。

## 覆盖范围与剩余工作

12 份都是官方行政文书，能检验多方金额/期间/主体、欠付与命令、组件与完整总额、历史撤销及证据不足等差异。划分独立性是案件/关联工程独立，不是机构或网页模板独立；部分开发与留出文书来自同一政府站点，存在共同写作格式。它们是争议后形成的结构化叙述，无法代表用户实际上传的工资条、手写欠条、银行截图、扫描 OCR 噪声、所有行业或所有地区；也不能排除公开文书已进入模型预训练语料。本轮没有声称从未训练见过的私有材料。

另一 Agent 的逐条复核覆盖 expected、alternatives、争议归属和具体漏标/负例；有原文依据的修改在首次留出推理前统一完成并重新产生哈希，之后冻结。开发审查者此前承担合同/技术审查；留出审查者此前承担网站存储/API/UI 集成，但未参与材料选取/金标编写、模型提示词或评分器，也未读取模型回答或成绩。因此独立性表述限定为标注作者独立，而非完全未参与应用实现。静态校验通过不能代替语义复核。主 Agent 在实现/提示词/评分冻结前只能使用开发集；正式留出评测、API 预算和停止规则另由主 Agent 冻结。开发阶段既有结果由主 Agent 按首版/修订金标版本分别保存，作者未读取这些回答。

本目录没有模型结果、模型成绩、训练产物或已运行的工资计算。程序合法核算场景如需完整 due/paid 配对，应另用明确标为合成的程序测试夹具，不把缺失金额补进这些真实材料。
