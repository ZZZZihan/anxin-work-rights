# 安薪乐业：事实表示 v2 与新材料对比

本轮解决候选表示与消费：把个人/群体、单笔/完整累计、签约/工作期间分开，接受有限的完整外层JSON围栏，保留原始输出和字面核验。继续使用既有Qwen3-32B-4bit与DeepSeek-v4-pro；无LoRA、RL、adapter或权重训练。跟踪Issue #38，依赖PR #36。

## 实际改动

候选使用schemaVersion=2及11个显式字段。金额的subject是享有/收取方；scope区分individual/group/organization/unknown，meaning与completeness独立表达。date区别contract_signing、contract_performance、employment_period、wage_period和payment_date。工资费率另存rateUnit，原文金额、引用与原始模型回答保持不变。未知金额不变成0。

例如合成材料“张某等三人工资总额9000元、预支张某500元、1月2日签合同”：9000属于群体范围，500属于部分付款，签约日期不授权工作期间。这些候选可展示和回看原文，但不进入个人完整总额提示。个人提示还要求用户已确认同一个人及明确工资期间、候选明确complete、金额可解析、无核对问题；候选仍不授予计算权限。用户必须核实并独立输入完整应付/已付，总额未确认不计算。

旧候选继续可读，标明尚未区分新属性，不自动推定个人/完整；既有人工确认不因schema升级被无故抹掉。新材料、重提取、撤回及版本变化继续使过期确认失效。同步修正案件归档/单位变更时正在运行任务的取消、干净范围表单刷新与未保存草稿保护，以及过长材料在提取前给出明确错误。

## 实验边界

3份开发材料23事实，8份全新留出材料63事实；11案与旧v4全部12个案件及关联工程人工去重，原文哈希/取得路径/节选定位保留。留出首跑冻结前，数据作者与独立审查者未查看模型输出，主实现只看开发输出；本文件及ERROR_REVIEW为运行后报告与审查。67个有限可接受备选在正式首跑前登记，全部标签仍是非法律专家暂定标注。

35个文件冻结，含输入、标签、最终提示、评分器、验证器、协议与模型身份。两模型同一输入同一提示、temperature0、每份首次生成，不因答案差而重试；未完结与漏提保留分母。Qwen每材料独立进程；DeepSeek仅发送前连接重试、发送后不重投，临时测试出口用完关闭。

开发阶段澄清受益方和日期/断言规则，历史消息和结果保留，详见DEVELOPMENT.md。开发结果与正式结果的提示不同，不能当作前后提升。v4任务schema也不同，不能用两轮F1差值宣称模型变强。

## 正式结果

| 后端 | 完成材料 | 原生JSON / 适配后有效 | 原始候选 / 通过字面校验 | basic F1 | strict F1 | 完全正确材料 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 规则 | 8/8 | 8/8 / 8/8 | 3 / 3 | 6.06% | 0.00% | 0/8 |
| Qwen3-32B-4bit | 8/8 | 0/8 / 8/8 | 72 / 43 | 15.09% | 5.66% | 0/8 |
| DeepSeek-v4-pro | 8/8 | 3/8 / 8/8 | 47 / 47 | 67.27% | 43.64% | 0/8 |

表中F1基于通过字面校验的候选，仍固定对照63个预期事实，拒绝/漏提不会缩小分母。通过校验仅代表字段与原文匹配约束通过，不代表业务事实正确。Qwen原始候选basic/strict F1为20.74%/5.93%，DeepSeek两种口径相同；完整TP/FP/FN与原始回答见comparison.json和各report.json。

Qwen全部8次正常结束，逐份运行时间合计444.89秒（约7.41分钟，含各进程加载），报告的推理延迟合计417.02秒；MLX峰值17.59 GiB，218次内存采样均为正常压力，swap存量约3.05 GiB且本轮采样未增加。DeepSeek合计43.29秒，8次连接对应8次POST，没有答案重试，临时出口已关闭。这是当前机器/网络、短节选、逐份执行的实测，不代表吞吐或其他长度材料的容量承诺。

Qwen的29个拒绝项为15个引用/值不支持、8个字段/条件无效、6个主体/期间无字面支持。另有21个已接受金额候选在现行金额解析器下均无法规范成数值，多数把“共计”“底薪”等也写入value，另含概数、中文金额或百分比。因此不能把15.09%的basic F1全部解释为金额含义理解失败。DeepSeek通过字面校验的47项也有漏提与属性分差，其中一份含8个预期事实的材料返回空数组；这次仍计为8个漏提。

basic是一对一比较金额/日期种类、意义、规范值，费率还比较单位；strict再要求主体、范围、期间、完整性和断言属性一致。F1兼顾误提与漏提，正式分母固定63。报告另外区分原生JSON、适配后协议有效、逐项拒绝、待核对、完全正确文书；格式有效不等于完整或语义正确。

## 对LoRA的判断

先不训练。外层围栏、未知/零、类型枚举、总额消费权限和过期状态应由程序约束；一份有明显金额/日期的材料却返回空数组，属于提取覆盖和失败处理，需要单独提示，不能把JSON合法当作任务完成。没有必要用LoRA代替这些确定性措施。

有希望作为后续LoRA研究目标的是：固定11字段输出、逐字数字/引文复制、同段多主体金额归属、付款事件与累计范围、签约/工作/付款日期的语义分配。必须先收集更多经复核、授权清楚、不同案件来源的训练样本，再另建未见测试集。本轮63条不是足以训练或证明收益的数据量，测试答案不能直接混入训练后继续当独立测试。

陈述属性claimed/decided/narrated、日期主体定义、部分日期角色、同义期间拆分等尚有标注或表示争议，详见ERROR_REVIEW.md。这些分差不能全部视作模型错误，更不宜未经专业核对直接当纠错训练数据。程序的多人/单笔词法提示也会因引用过长产生误报，尤其“三人”被错误匹配到“第三人”；提示只用于人工核对。金额跨度规范、空提取覆盖提示、第三人及长引用误报作为运行后发现保留在[Issue #39](https://github.com/ZZZZihan/anxin-work-rights/issues/39)，没有为改善本次分数而改动冻结代码或重跑。

如果以后训练，训练产物将是本地Qwen的LoRA adapter，用于候选提取这一小任务。它不能加载到DeepSeek托管API上；DeepSeek可继续作为独立提取或复核后端。是否值得上线要看新测试集上的语义准确率、覆盖率、延迟和运行成本，而不是只看训练loss下降。

## 可复核材料

- PROTOCOL.md、freeze.json：预登记定义与冻结摘要。
- data/、SOURCE_REVIEW.md：来源、分组、暂定标注、有限备选及独立数据审查回执。
- results/holdout-*-1/：每种后端的原始输出、完整消息、运行事件、评分和失败记录；result-manifest.json绑定正式结果文件。
- comparison.json：描述性聚合；ERROR_REVIEW.md：逐类误差及LoRA边界。
- REVIEW.md：冻结前复核；verification/：整合、隔离HTTP和浏览器记录。

重算不调用模型：`node experiments/material-facts-v5/verify.mjs`；`node experiments/material-facts-v5/summarize.mjs --check`。正式目录拒绝覆盖，也不能再对已揭晓数据重生成挑最好结果。

来源为官方公开文书或案例报道的必要节选，4份正文经记录的代理取得；不等于私人原始工资表/银行流水，不证明原件真实性、账目完整或真实业务收益。公开可读也不等于开放训练或再分发许可，整页仅留本机私有缓存。旧失败、旧复测和未合并PR均保留；本轮没有合并、部署、训练或用户人工验收。
