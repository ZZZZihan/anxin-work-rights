# 金额规范化、局部事件核对与新材料评测

本轮先修流程，再用新公开材料观察模型残差。没有训练、没有 LoRA adapter，也没有更改模型权重。旧 v4/v5 的代码快照、数据、失败调用和结果保留可重算。生产运行时的进一步防御与冻结模型评测分开记录，不能用程序拦截后的表现替换模型首次回答。

## 已实现的行为

- 原文金额与规范值分开保存。“工资共计8000元”保留原文，同时记录 `8000.00`、实际匹配的 `8000元` 和位置。明确零可以是零；范围、概数、遮盖、多个金额、未知与不支持的写法保持不能精确解析，不能补成零。
- “第三人”不再因“三人”子串被当作班组。真正的多人/班组线索仍提示核对。长引用先定位当前值所在事件，别句签约不再自动把本句任职日期判错；同值重复、无法确定事件时保留不确定。
- 空候选、全部拒收和可能未覆盖的金额/日期有不同提示；持久化原始答案和拒绝原因。旧版空记录也有提示。提示不会自动补事实、确认金额或授权计算，“未发现额外线索”不表示提取完整。
- 日期主体按对应劳动者或工资受益群体标注；实际任职、签约、合同履行、工资覆盖和支付日期分别表示。`date.period=null`；有日历锚点的工资期间既在金额 `period` 保留，也作为独立日期提取。没有日历锚点的“试用期”等阶段不凭空补日期。完整定义及有限别名见 [ANNOTATION.md](ANNOTATION.md)。

冻结后，PR 自动审阅和独立复核又发现模型可能裁掉 quote 的相邻限制词。生产链路新增独立 `material-fact-source-review`：直接绑定当前原文块、唯一引文及字符位置，核对对应金额所在片段；只降低不可靠的金额可用性或增加提示，不改原答，也不替人确认。典型例子：

| 原文及模型截取 | 当前生产行为 |
| --- | --- |
| 班组10人完整应付80000元，模型只引用金额并标个人 | 提示主体冲突，不作为个人完整总额提示 |
| 原文“约80000元”，模型只引用“80000元” | 保留原答，规范状态降为概数，金额为 null |
| 原文“80000元”，模型只引用内部“0000元” | 拒绝把截断数字规范成0，不猜回80000 |
| 原文“0.01元”，模型只引用“01元” | 金额边界不完整，不规范成1元 |
| 原文“8000元/月”，模型只引用“8000元”并标总额 | 提示费率与总额角色冲突，不产生总额提示 |
| 原文“本次支付80000元”，模型标完整已付 | 提示单笔与完整累计的冲突 |

这一检查仍是有限词法防御：不会普遍继承逗号前的群体主语，同一句中多个事件也可能需要人工判断。它不是一般事实理解正确性的保证；已有用户独立核实的金额确认不会被无提示改写。冻结 v6 使用首跑前的 v3 提取与评分，不把后加的生产守护计成模型改进。`verification/source-guard-audit.json` 仅对原始回答追加诊断，正式分数不变。

同时增加独立取消记录：D1 在事实删除或旧任务被替换的同一事务中保存任务编号；取消服务若超时，后续本人案件请求可重试。旧任务编号、所属用户/案件和入队时间之外不保存材料或模型答案；每次最多5条，首个服务失败即停止。无案件变化不取消当前工作，旧任务不会覆盖或取消新任务。重试依赖后续本人请求，不宣称已经有无人值守的全局后台清理。

## 数据与证据边界

3 份开发材料、8 份独立留出材料，对应 29/50 项非专家暂定参考事实；19 项有限别名或边界备选在首跑前登记。按案件及关联工程与 v4 的 12 案、v5 的 11 案去重，不能把同案转载当独立样本。7 份官方原始页面/文件经直接访问取得，原文必要节选、定位及哈希见 [SOURCE_REVIEW.md](SOURCE_REVIEW.md) 和 `data/`；完整原始缓存仅留本机。

这是一组公开叙述材料的文本提取评测，不是真实私人案件处理效果，也不覆盖 OCR、扫描件噪声或法律专家验收。公开可读不等于允许批量训练或再分发。新公开材料没有覆盖所有未知/显式零边界，这些由单独的合成程序回归验证，不能混作真实模型样本。

36 个文件在正式调用前冻结，包括提示、实现、标签、备选、模型身份、运行及评分器。每份材料首次回答保留；相同提示、输入、温度 0、非思考模式、4096 输出 token 上限。金额字段的精确匹配只规范 value，不让 quote 长度改变计分；安全诊断另用完整引用。所有空输出和漏提仍留在 50 项分母里。

Qwen 使用本地 Qwen3-32B-4bit，每份材料独立进程，保留内存保护；DeepSeek 使用官方 `deepseek-v4-pro` API。开发轮旧出口在 TLS 阶段失败，9 次连接、0 次 POST，证据保留；本机直连完成开发轮后冻结为正式路线。正式 DeepSeek 8 份均一次 POST 完成，未因答案不佳重投。

## 正式结果

三方正式评测均完成 8/8，原始结果、首次调用记录与报告已封存，汇总见 `comparison.json`。Qwen 先等待另一项本机实验正常结束，再按原协议完成 3 份开发诊断与 8 份独立留出材料；没有中断另一实验，没有放宽内存保护或因答案不佳重投。

指标按逐事实一对一最大匹配计算，而非逐材料平均；basic 核对数值/日期原文、类别、含义和计价单位，relational 再核对主体、范围、工资期间、完整性，strict 再核对陈述属性。原始层与通过协议/字面校验层分别保留。通过字面校验不是事实确认。

| 通过协议及字面校验层，固定 50 项事实 | 完成材料 | basic F1 | relational F1 | strict F1 |
| --- | ---: | ---: | ---: | ---: |
| 窄规则基线 | 8/8 | 0.00% | 0.00% | 0.00% |
| Qwen3-32B-4bit | 8/8 | 25.97% | 7.79% | 5.19% |
| DeepSeek-v4-pro | 8/8 | 51.85% | 48.15% | 27.78% |

原始输出层的 basic / relational / strict F1 分别为：Qwen **35.40% / 17.70% / 8.85%**，DeepSeek **51.38% / 47.71% / 27.52%**，规则三项均为0。原始层也按预登记谓词核对所含字段，不因为被接受层拒收就删除原答。接受层F1下降不等于程序应放过错误引用。

| 首次输出与字面协议 | 原生纯 JSON | 原始候选 | 接受候选 | 拒收候选 | 严格全对材料 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 窄规则 | 8/8 | 0 | 0 | 0 | 0/8 |

Qwen 的8份回答都带外层 Markdown 代码围栏，冻结解析器可去掉围栏后读取，不记为原生纯JSON。36条拒收分别为17条引用/候选字面不对应、15条条件字段或枚举违规、4条主体/期间无原文支持；正式15条形状错误均缺少日期 subject/scope，其中7条还缺 rateUnit，period 均为 null；缺字段先考虑结构化约束与接口简化。开发集另有 completeness 违规，同样单列，不能全部算作值得微调的语义错误。

Qwen 正式8份生成耗时合计379.82秒，独立进程合计403.93秒；MLX峰值17.63 GiB，外部196次压力采样全部正常，已有swap未增长。DeepSeek合计75.56秒，官方直连8次连接、8次POST。硬件、传输和服务条件不同，这些是本次运行记录，不是通用速度排名。

新生产守护对三路已接受候选的冻结后诊断均为 **0项变化**，没有改变正式分数。其源文裁剪防御目前由合成回归及界面验证支持，不能宣称本批真实材料模型成绩因此提高。

规则在本组 8 份公开叙述材料上均无候选，precision 无定义，不能写作 100%。DeepSeek 为 59 个原始候选、58 个接受候选、1 个字面引用拒绝；没有完全正确的材料。basic→relational 的 2 个匹配损失均含主体/期间同义跨度限制，不能全部解释为把班组金额算给个人；relational→strict 的 11 个损失来自陈述属性。逐案复算和错误证据见 [ERROR_REVIEW.md](ERROR_REVIEW.md)。

**计分边界：同额不一定同一事件。** 鞋业材料同时有资产变卖105.7万元和发工资105.7万元。Qwen把前者标payment，把后者标完整paid_total；前者可能因同额同角色在basic匹配到工资标签，但quote实际指向资产变卖，主体/范围核对后未匹配。冻结basic不验证事件引文语义，不能把这种命中解释为理解正确。重复同额的聚焦诊断保持ambiguous；下一轮应预登记事件对齐要求，不追改本轮分数。

## 哪些错误还不能交给 LoRA

**确定性解析和表示先修。** “人民币四万元”与“四万元”意思相同，目前普通中文小写金额尚未规范为同一个比较值；“约115万元工资”与“约115万元”的额外名词也会导致严格跨度不匹配。“洪某等3人”与“工人洪某等3人”、相同起止年月的纯连接词差异同样要单列。不能把这些评分损失包装成模型不会理解金额或主体，更不能用 LoRA 代替解析器。

**标注范围先澄清。** 欠薪余额观察截止点和工资覆盖期、工程施工期和某位劳动者任职期、相关财产处置日期是否在任务内、年假工资的类别，需要补清楚边界例子并独立复核。当前分数不回改；争议样本不能直接作为 LoRA 硬目标。

**真正的语义残差继续收集。** Qwen把“洪某等3人”的工资候选标为个人范围，又把付款人“张某某”填为80多名工人工资的受益主体；还把一笔工资发放视为完整已付，并在同额的资产处置与工资支付之间混淆事件。DeepSeek 将“缴纳5万元用于支付”标成劳动者已收到的单笔支付，将行政责令发生日标成支付日，将付款义务人写作工资受益主体，以及没有继承明确“本委经审理查明”的陈述属性。这些是有业务后果的语义问题，适合继续收集独立案例；是否进入 LoRA 仍要排除简单规则可以稳定解决的部分，并经更多样本和标注复核。

**遗漏保留为失败。** 一份鞋业材料有 5 项明确金额事实却返回空数组，是本轮 DeepSeek 的真实提取遗漏；提示能让用户核对原文，但没有补回事实。另一份材料把没有金额的工资描述列成 money，应先研究简单的金额存在性检查。不能凭当前单案空提取就声称已经找到稳定训练收益。

本轮结论不以 v5/v6 的分数差值证明模型提升：材料、参考事实和协议有变化。训练仍推迟到程序错误与标注争议清理之后，用更多独立样本检验剩余语义错误是否稳定存在。
