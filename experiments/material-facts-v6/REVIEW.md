# v6 冻结前独立技术与数据审查

本记录由未参与领域或界面实现的审查 Agent 编写。审查者会在冻结前审查来源与研究标签，在正式冻结前不读取本轮任何模型输出；主实现者只接收开发材料、聚合结论及原则性异议，不接收留出答案。本轮不训练、不修改模型权重，v4/v5 冻结材料和结果保持原样。标签是非法律专家暂定研究标注，技术复核不等于法律专家或真实用户验收。

## 预先确定的任务边界

以下约定于选材和模型运行前提出，经主实现者确认，须与正式提示、协议和标注说明一致；不能根据本轮模型回答事后增加接受备选。

- 日期主体统一指该日期关联的劳动者或班组受益方，不能自动取付款公司。仅凭输入内部明确指代选择连续原文姓名、简称或群体名；未知保留 `null` 和适当的 `unknown` 作用域，不从来源整页或文书体裁补信息。有限姓名和简称备选在冻结前登记。
- 日期 `value` 取最小连续原文日期串，保留影响边界的“前、后、起、截至”等词，不补年份、月初或月底。“于”等纯介词可以省略；“自……至……”等连接词形式的有限等义备选应预先登记，不能省略实质边界词后仍视为同一精度。
- 入职和离职均用 `employment_period`；签约用 `contract_signing`，合同履约区间用 `contract_performance`。明确工资覆盖用 `wage_period`，包括有明确工资覆盖语境的停工留薪期间；调薪生效日、工伤发生日等直接影响金额的实质事件用 `other_date`。同一区间若明确承担任职和工资覆盖双角色，分别保留；仅“工作三个月”默认任职时长，不强推工资覆盖。
- 日期候选的 `period` 必须为 `null`。金额 `period` 保留原文工资归属；其中包含具体日历或有明确日期锚点的工资期间，仍须另生成独立的 `date/wage_period` 候选；“试用期”“离职前”等无日历锚点的工资阶段可只保留在 `money.period`，纯无锚点时长不输出独立日期。同句、同主体、同角色并列的多个区间整体保留为一条连续原文，不凭空拆分或补全。
- 陈述属性只来自模型实际收到的明确上下文，不因官方文书体裁推定 `decided`。明确查明、认定或命令用 `decided`；其中转述当事人主张仍用 `claimed`；明确确认、承认用 `admitted`；中性叙述默认 `narrated`，陈述归属确实不明用 `unknown`。局部引导语的作用域不得跨越到明确由另一方提出的主张。
- 同一事实同一陈述属性去重，不同明确陈述属性分别保留。身份按 `kind/meaning/规范值/subject/scope/period/completeness/rateUnit/assertion` 判断，`quote` 和 `blockId` 不产生新事实；同值不同角色、不同明确主体或不同明确期间仍为不同事实。
- 与 basic、strict 并列预登记 relational 指标：在 basic 上比较主体、作用域、期间和完整性，排除 assertion；费率单位仍按 basic 要求比较。不得以 relational 代替 strict 或将陈述属性分差全部描述成主体、期间或计算完整性错误。
- `payment_as_paid_total` 只表示角色混淆；单笔/部分付款被当成完整已付须另以明确 `completeness=complete` 的诊断记录。词法待核对提示、字段拒绝、事实语义错误和实际工资计算授权分别报告。

## 实际完成的独立审查

审查者逐项阅读并核对了 3 个 dev、8 个 holdout 的输入与 79 条暂定标签，以及 19 个有限备选候选；未读取本轮任何 Qwen、DeepSeek 或规则输出。开发集 29 条、留出集 50 条。已将开发集可运行结论先行交给主实现者；留出具体答案不向主实现者传递。

来源方面，独立重新读取并校验 7 份官方原始缓存的字节 SHA256，按回执精确重建全部 11 案的 23 个输入块及块/节选 SHA256；20 个 HTML 输入块另由独立 HTMLParser 从原始 HTML 文本核对。PDF 以独立 PyMuPDF 提取、移除独立页码和布局换行后，与作者派生正文完全一致；另实际查看第 4、5 页渲染图，核对合同日期、工资结清陈述及中文金额。未把派生正文哈希误称原文件哈希。对案件独立性复核涵盖旧 23 案与新 11 案公开可识别的当事人、时间、地区、工程/工作关系和 family；匿名材料不能证明隐含真实身份绝无关联。

标签审查重点是工资受益人和付款方分离、非工资金额实际收取方、同额不同事件、工资归属和付款日、合同签署和任职、明确完整累计、概数保留、陈述属性及同事实去重。冻结前已解决的实质问题包括：连续费率单位遗漏、无明示计价单位却推定月薪、年工资子项被标成完整应付、承诺欠款缺少明确自认层级、非工资款把承担方当收取方，以及法人主体的 scope。涉及含混部分清偿的材料在未看输出时替换成有明确累计支付原文的独立案件；数量保持 3/8。上述修改均在首次正式留出调用前完成，不能在运行后按输出修改。

实际使用主树 v3 领域及 v6 评分器回放全部参考标签：79/79 候选接受、0 拒绝，11/11 整案 self-match；dev strict 29TP/0FP/0FN，holdout strict 50TP/0FP/0FN。逐个将 19 个有限备选替换入所属整案后，仍全部接受且 strict 完全匹配。这些检查证明结构与评测接口一致，不是模型成绩，也不单独证明标签法律正确。

## 技术审查与已修问题

已只读审查新 v3 表示/领域、v6 提示/协议、assess、freeze、verify、run 及版本化运行包装。旧 v2 读取保持原规范值，不就地升级；v4/v5 冻结文件没有由审查者修改。新批次重置原有人工确认与计算结果；候选诊断、金额规范化、人工确认和计算授权仍为不同阶段。

独立实际复现了 18 个金额及上下文边界：日期前缀中的唯一人民币金额、显式零、金融大写角分、另一笔省略币种、中文另一金额、空格负号、外币、区间、遮盖、上下限、模型裁去约数/符号、另一人的约数不污染本项、同值多次出现不选首个。初稿的运行导入缺后缀、空格/Unicode 符号、第二个裸数和插词上下限误解析均已由实现者修复。最新基础领域版本为 94 项作者测试；其后主实现只修去重身份并补回归，整合检查由主实现另记。

最后一次独立复现发现：同一事实短 quote 可精确规范化、长 quote 因重复值为 uncertain，若去重键取带 quote 的规范值，会保留两个重复事实。主实现已改为以 value 自身的语义规范值去重，完整 quote 诊断不变；审查者实际验证正反两个顺序均只接受 1 条并拒绝 1 条，而不同明确 assertion 的 2 条仍保留。复现时主树 `lib/material-facts-v3.ts` SHA256 为 `b1e5fbe9829cd677c98315070fd3406dfadd6305a3291dfa601a3df64874cbdd`。

评分器以 value 自身作语义匹配，另报完整 quote 的 normalization；不会因引用长度把正确字面金额误算成金额识别错误。参考 value 保留直接限定词，裁去“约”等仍不匹配。raw 重复保留为 FP，接受层先去重；未正常结束的输出不进入 accepted、coverage 或 normalization，但 raw 统计保留。basic、relational、strict 使用一对一最大匹配；诊断只在先消费正确匹配后，对唯一剩余值配对归因，不强配同额多人。

冻结/验证代码检查覆盖输入/消息/领域/评分器哈希、全部 data 文件、旧 v5 递归验证、不可覆盖的正式目录、一次 POST 与发送前连接尝试分离、运行事件/结果/协议回执、固定全部计划案件的召回分母。最终结果仍须由审查者在实际输出出现后独立复算；当前没有真实模型效果或最终运行完整性的结论。

## 预先保留的限制

- 金额解析刻意保守；普通小写中文金额等支持不足会保留原文和 null，不能把 parser 的 unsupported 等同模型没有识别金额。开发标签已有此类值。
- 局部事件按逗号等标点分割；群体主语与金额被逗号隔开的省略句可能漏提示。诊断不是语义分类器，也不能证明已覆盖完整；未为追求提示召回而重新扫描整段长 quote。
- date 覆盖信号只覆盖有限日期样式；空提取提示、possible_missing、no_signal 不是完整性或计算授权结论。
- 本轮缺少真实工资显式零及未知遮盖金额新材料；这些有合成/旧集程序检查，不能据此声称新留出实测覆盖。语料含同一发布汇编的不同案件，独立单位是案件家族而非网站数量。
- 陈述属性、日期边界和工资子项完整性依赖本轮预登记约定；标签仍为非法律专家暂定标签。正式结果须同时报告 basic/relational/strict，运行后争议单列且不回改金标。

## 冻结前结论

来源、全部标签、有限备选及关键技术边界的独立审查已完成；没有未解决的标签语义阻塞。最后发现的来源清单外层格式已统一为 `sources` 包装对象；冻结程序原将同一事实互斥备选当作同时预测校验，现改为逐个验证，避免正确去重错误拒绝同义备选。审查者实际重新调用主树最终 `validateData` 已 PASS：3 dev / 8 holdout、29 / 50 主事实、19 备选，包含旧集 URL/案件/family 排除和来源绑定。本文件不替代主实现的整合检查和运行就绪检查。可以冻结并按协议进行首次留出调用；此后不得改本文件、标签、提示或评分器，运行后审查另写 `ERROR_REVIEW.md`。
