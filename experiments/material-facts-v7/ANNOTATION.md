# v7 标注与事件对齐约定（新材料首跑前）

本协议用于 Issue #42 的新批次，不回改 v1–v6 的标签、备选、输出或分数。标签是 `provisional_non_expert` 研究参考；数据作者和未参与实现的 Agent 在模型首跑前独立复核，均不构成法律专家或用户人工业务验收。争议必须在首跑前记录处理依据；首跑后发现争议只追加异议，不能回填标签或备选。

## 数据隔离与任务范围

按案件及关联工程分组，与 v4、v4 replication、v5、v6 排除重叠；同案不同网页或文书不是独立案例。开发集与留出集也按案件隔离。输入只含原文块 id/page/text 及运行必要封装；模型消息不含标签、事件编号、备选、错误诊断或评分规则的具体答案。正式运行前冻结全部输入、标签、规则、提示、代码、模型身份与参数。所有计划材料保留分母，空输出、超长、协议失败和传输失败均记录。

提取工资及直接相关金额，以及工资归属、任职、签约、履约、实际付款/明确日历支付截止等实质日期。人数、案号、法条、比例、无锚点时长不作为金额/日期。工程款、赔偿、罚金、相关财产变价等非工资金额可为 other_money，不成为工资总额。与工资核算无直接关系的财产处置日期、公司注册、纯受理/立案/送达/开庭/裁判作出/发布/行政责令发生日及程序相对期限不提；不能因同句存在工资金额就把这些日期变成支付日。

## 原始输出和确定性表示

继续使用 schemaVersion=3 与完整11字段：kind/value/quote/blockId/subject/scope/meaning/completeness/period/rateUnit/assertion。每一项都必须出现；不适用的字段显式 null，不由程序猜 subject/scope。日期的 period/rateUnit 为 null，completeness 为 not_applicable。缺字段和不合法字段原样保留在 raw，并作为协议拒收记录；不通过自动补语义字段“修好模型”。

quote 必须是单个原文块的连续逐字子串，value 必须是 quote 中连续逐字子串。subject 与非空 money.period 必须有模型可见原文支持，不能从未展示的全文补姓名/年份。金额保留精度、币种、费率、概数、界限、区间和遮盖；未知不是0，只有明确0才为0。不得相加、相乘、推导差额或换汇。money.value 取完整金额片段；“2020年12月基本工资”等无金额的工资描述不是 money，单独提符合范围的日期即可。

普通中文小写金额与金融大写/阿拉伯数字只在确定性解析支持、数量和币种一致时等价，例如“人民币四万元”“四万元”“40000元”。不猜“一千一”等省略。概数/上下界/范围/遮盖与精确金额不等价；“约四万元”不能命中精确“四万元”。纯金额前缀人民币与有限末尾金额对象词（工资、劳务费等）允许由首跑前固定的比较函数规范，原 value/quote 不重写。所有等价函数与测试在冻结内，不按模型回答加规则。

群体名省略“工人”等修饰、日期纯连接跨度（如“自2020年9月至2021年2月间”与“2020年9月至2021年2月”）仅通过首跑前逐事实登记的 acceptable_alternatives。不得泛化删除主体信息、前/后/截至/起/止等实质边界，备选也不能改变事件或事实分母。

## 金额角色、主体和日期边界

- due_total/paid_total 是明确主体及结算范围的应付/已付累计描述；只有原文明确全部累计才 complete，明确组成/部分为 partial，其他为 unknown。欠款使用 arrears，不因欠薪就推为完整应付。
- 单笔/部分/预付款为 payment/partial，未明确完整性的一般付款为 payment/unknown；缴纳保证金、转入法院、资产变现或“拟/用于支付”不等于劳动者实际收到工资。裁判/行政命令给付工资的金额为 award，不能当实际付款；经济补偿、赔偿金仍为 other_money。
- 工资及相关日期主体为劳动者/受益群体，不是付款人、欠薪人或资金出借方。非工资款按明确收取/享有主体；未明用 null/unknown。姓名代表多人仍 group。
- 余额快照“截至某日仍欠X元”的日期为 other_date；它不自动表示工资覆盖开始/结束。只有“某月工资”“某日至某日应付工资”等明确归属才为 wage_period；money.period 与对应 date wage_period 都保留。
- 合同签署日为 contract_signing，约定履行期间为 contract_performance；实际入职/离职/任职期间为 employment_period。项目施工起止只描述工程时，不能推定各劳动者任职；明确表述某劳动者/班组实际工作起止才可标任职。争议未能消解时列为范围排除并留异议，不造精确标签。
- 年假工资属于工资组成：明确承认某年度年假工资的应付额为 due_total/partial（不是全部年度工资），裁判命令对应 award/not_applicable；经济补偿、赔偿金等为 other_money。此为本轮研究分类约定，须单列非专家性质与可能的法律术语争议。
- 实际支付日、明确日历支付截止日及“每月15日”等明示周期支付日都用 payment_date，保留原文，不合成年月。纯程序性相对履行期限排除。
- date.period 永远 null；无日历锚点的“离职前”“试用期”可作为 money.period，但不合成 date。并列同主体同角色期间按完整连续原文，同一日历跨度承担两个明确角色可各提一条。

assertion 按可见上下文：明确查明/认定为 decided，明确承认/双方认可为 admitted，当事人主张/证言转述为 claimed，中性叙述为 narrated，不明为 unknown。官方发布不是自动 decided；“经查”中引用“某称”仍按其自身叙述层级。历史自认、后来的否认和裁判认定可为不同事件/陈述，不以训练方便强行合并。

## 事件证据（仅标注/评分侧，绝不送给模型）

标签保留 expected 和 acceptable_alternatives，另有：

```json
{"events":[{"id":"event-1","anchors":[{"blockId":"b1","start":12,"end":18}]}],"expected_event_ids":["event-1"]}
```

start/end 是原 block.text 的 Unicode 码点半开区间，锚定金额/日期 value 发生位置，不是整句，也不是UTF-16字节偏移。同一明确陈述或行为事件重复叙述可登记多处 anchor，并可支持不同 meaning。历史自认、当事人主张与裁判认定默认分属不同陈述事件，不能因其涉及同笔债务而共用事件；不同 assertion 上下文必须分别锚定。不同事件即使金额、主体、日期均相同也不能共用 event id。每个 expected 必须有事件，有限备选继承对应事件。

评分先验证候选完整字段及逐字证据，枚举 quote 在指定块中的全部位置，再枚举每个 quote 内 value 的全部位置。每个可能位置必须与一个登记 anchor 相互包含（允许币种前缀/有限名词后缀/日期纯边界），全部可能位置只能归到同一事件。存在未登记位置、不同事件、多义或缺证据就不能命中；绝不取 indexOf 的第一个位置，也不使用模型自报的 meaning/subject 反向挑选事件。大段引用里有两处同额不同事件不能蒙对。

所有 raw/accepted 的 basic、relational、strict 匹配均要求事件相同。basic 再比较值、kind、meaning、费率单位；relational 加主体、范围、期间、完整性；strict 再加 assertion。非法 raw 项保留在FP分母；缺请求/空输出保留FN。事件对齐不自动判定模型事实可信，仅避免同额跨事件得分。生产守护另外报告降级、拒收和可用性，不把协议接受或评分命中视为人工计算授权。
