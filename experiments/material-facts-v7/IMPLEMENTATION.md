# Issue #42：解析、源文事件与评分修复

本项为后续新材料实验的前置工程改动。所有旧v3–v6提示、数据、回答、分数及封存文件保持原样。新parser/提示在独立v4模块，新的事件评分在v7目录；尚未训练、合并或部署。

## 可复现问题与最终行为

- 普通中文小写“人民币四万元”原来无法与“四万元”及40000元比较。新解析支持明确完整中文数值及角分，使用整数分精度；原value、quote和Unicode码点位置不变。概数有限工资名词后缀和人民币前缀只生成比较键，派生amount仍为null。省略位数、中文小数或算式不猜结果。
- “2020年12月基本工资”“某月工资”等没有金额，旧协议会接受money候选。新增三态检查，只拒绝确定没有金额的描述；明确未知、遮盖、范围、不支持的复杂表达继续保留供核对，不能变零。
- 同额资产变卖和工资发放在旧评分里可以跨事件命中，连strict也无法仅靠相同属性避免。新标签登记源文事件与码点锚点，评分枚举全部quote/value发生位置；raw/accepted的basic、relational、strict六层都先要求同一事件。缺字段、非法候选留在raw FP，失败/空输出保留固定FN分母。
- 生产去重以前可把两次同额同属性付款合并。现在只有同一原文发生位置才允许去重；不同位置保留，两次重复陈述也可能保守保留，须人工核对而不自动相加。原始输出始终保留所有项。
- HTTP验收发现月份工资被当费率，修正了“2026年1月工资”等日期边界及OCR水平空格；真实月/日/时工资的费率防护保留。

## 新提取、历史记录与人工确认

新提取先解析原始金额，再按完整源文的局部事件检查币种、概数、范围、费率、主体和期间，并保存审查后的派生状态。读取历史记录只允许降级，不会把旧unsupported值悄悄升级；显式重提取沿用原流程使旧范围和金额确认失效。协议接受、精确金额及评分命中都不是人工业务验收或计算授权。

新提示保持完整11字段，不替模型补subject/scope/rateUnit。提示明确余额截止日、工资覆盖期、施工期与任职、周期发薪日、年假工资、工资裁令与经济补偿类别；加入完整date结构示例。未新增JSON mode或约束解码，后者需要另设冻结对照，不能凭本轮成绩断言其效果。

## 验证证据与边界

独立Agent预先构造事件评分反例，再对解析与实际处理链交叉复核；独立日志、技术回执及HTTP报告随目录保留。最初Node导入失败、兼容性失败、无金额漏网和HTTP费率误判均有本地原始日志；工程报告区分这些失败与修复后的检查。

HTTP脚本使用真实隔离Worker、D1/R2及材料服务，模型回答由明确合成fixture注入；包含成功、拒收、无效JSON、空输出、未完成回答和重启复读。它没有调用模型，不能代替新公开材料的模型实验，也不等于用户真实案件、法律专家或人工业务验收。

新材料、冻结运行工具和首次模型对比通过后续依赖PR交付。Issue #42在PR合并前保持打开；新的PR不继承此前#31/#36/#40的合并授权。
