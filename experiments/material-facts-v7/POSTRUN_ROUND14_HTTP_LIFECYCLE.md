# 第十四轮回归程序进程清理复核

PR45 在 `92ba4dd615eb3b5a43508902e3e217b96ea6df9c` 上新增两条审查：4306251287（Linux 僵尸进程导致假清理失败）与4306251289（取消回归程序遗漏重定向输出且忽略TERM的后代）。即使此前该提交CI通过，两个问题仍可实际复现，因此继续修复并另存证据，不改旧回执。

四条相关材料事实HTTP回归程序（v7、取消、并发轮询、网络恢复）现在共享自有进程组清理。启动时登记所有权并监听close；退出时同时检查启动进程close与组内非Z/X成员，必要时KILL整个自有组。系统查询只读取PID、进程组ID和状态，不读取命令行或环境。正常的组ID零行允许解析；查询失败不会被当作进程已退出，仍尝试KILL自有组并报告失败。每个TERM/KILL阶段默认5秒，加至多一次系统查询及其关闭余量1.5秒，属于有界等待，不声称严格5秒绝对截止。

四条程序的迁移子进程也使用相同所有权机制。迁移失败与清理失败分别保留；单独清理失败会阻止继续启动Worker。无法确认清理时保留私有临时目录，并使回归整体失败，不删除仍可能被进程使用的状态。Windows仍只有原有单进程降级路径，本轮不声称实测Windows整棵进程树清理。

修前与修后使用相同实际子进程、监听端口、重绑端口及无关兄弟进程检查。Linux独立夹具通过专用Python子收养进程暂时不回收已退出孙进程，明确观察Z状态，最后自行回收；未修改内核或全局服务。具体红绿数量及最终源码哈希见本轮独立回执与 `postfreeze-evidence/round14/`。

中间失败同样保留：第一次helper把阶段末尾约1毫秒作为ps查询时限，现有5项生命周期测试出现3通过2失败；最终改为固定有界查询预算。主侧曾在旧测试提取器尚未更新期间提前运行，出现定位函数失败，该日志为整合时序错误而非产品缺陷复现。两者不混充为固定旧提交的红基线。
