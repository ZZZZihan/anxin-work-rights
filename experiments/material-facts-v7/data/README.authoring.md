# v7 新材料数据作者说明

本目录只准备 Issue #42 的全新官方公开材料，不调用模型、不读取新模型输出、不训练或部署。数据作者使用 agent-reach 的 Exa 搜索、官方直接读取与 Jina 失败后备路径。当前固定为3份开发材料和12份留出材料，按15个可识别案件/关联工程分组；源文与标签仍待独立复核及主树冻结，不能把本说明当成冻结回执。

主实现者在首次留出运行前只读取 `dev.*` 和本说明中的聚合信息；`holdout.*`、`sources.selected.json`、独立性明细及具体异议交由独立审查者核对。全部标签是 `provisional_non_expert`，技术复核不构成法律专家结论、用户人工业务验收或真实案件核算授权。

## 当前规模与覆盖

15个案件来自7份原始官方网页，开发集13条、留出集43条，共56条暂定事实；2份材料自然不含任务范围的金额/日期事实，保留空expected。来自同一官方汇编的案件属于共享来源依赖，不能把15个案件声称为15个独立文档或统计独立样本。数据同时包含中文小写金额、概数、同金额不同事件、群体与代付人、部分支付与全额兑现、余额快照、周期支付日、合同期限与实际工作期、年假工资及程序日期边界。

本轮没有找到并纳入明确的工资0，也没有明确承认应付年假工资数额的自然材料；不得以公司账户无存款、未支付或公式数字制造这类覆盖。材料选择发生在任何新模型运行之前，依据预登记的目标边界与可读官方原文，不按模型得分筛选。

## 原文、缓存与哈希

完整HTML、未入选候选和Jina后备结果只留在权限700的本机私有缓存 `/Users/xuzihan/.cache/anxin-material-facts-v7/`。仓库只保存必要连续节选、来源元信息及回执，不上传全文。输入均来自直接取得HTTP200的原始官方HTML，不以Exa摘要/Jina后备正文替代入选原文。

`acquisition-receipts.jsonl` 保留原始取得时的状态和初始通用段落解析结果；`acquisition-extra.jsonl` 保留PDF失败与Jina后备取得。`parsing-revisions.jsonl` 记录有正文但p标签不足的两个页面如何从同一原始字节重新解析；原回执不覆盖。特别是398582正文主要使用br/div，初始p-only方法只取2段20字，修订后按`.txt_txt`正文非空行取得107段7179字。该原始HTML不是challenge或404页，独立审查者可直接重建。

各hash含义分开：

- `raw_original_sha256`：原始HTTP响应正文HTML字节。
- acquisition/revision中的 `normalized_text_sha256`：规范化段落文本按两个LF连接的UTF-8字节。
- `normalized_paragraphs_sha256` / `normalized_paragraphs_json_sha256`：缓存`.paragraphs.json`文件字节，因JSON包装而与文本hash不同。
- 输入`source.sha256`/回执`excerpt_sha256`：本材料blocks按顺序以两个LF连接text的UTF-8字节。
- 回执`block_sha256`：该连续节选块text的UTF-8字节。

`*.excerpt-receipts.jsonl`给出原始文件、规范化文件、零基段落号及Unicode码点半开区间。只去正文段落首尾空白并将NBSP转普通空格，不修数字、错字、金额或日期。各输入块必须是规范化段落的连续原文片段，不能拼接不相邻词语。HTML逻辑page为1，不能声称为原始工资单、银行流水或私人上传材料。

## 取得失败、排除与权利边界

一份南山公开裁决与一份深圳PDF直连出现TLS BAD_ECPOINT，一份番禺网页读取超时；均保留失败回执且未入选。深圳PDF随后Jina后备读取HTTP200，但本轮有足够直接官方原文，仍未入选。低质量/非官方搜索结果仅为排除线索，没有用其摘要填充源文。agent-reach本地命令未安装，`check-update`返回command not found；实际搜索使用已连接的Exa工具，未修改或安装全局配置。

官方公开可读不等于取得开放许可证。本轮未发现或获得专门开放许可，未完成所有站点通用版权条款的法律审查；小规模必要节选仅用于本次用户已授权的内部研究评测，不能推导一般训练、批量抓取、商业利用、整页再分发或其他API传输授权。数据作者没有向Qwen/DeepSeek发送任何材料。

仓库节选只保留公开匿名化劳动者称呼及案件必要描述，没有增加身份证号、银行账号、联系电话、家庭住址、代理律师联系方式或凭据。匿名化来源限制了隐藏真实身份的穿透核对，本轮只排除公开信息可识别的同案/关联工程；URL或family字符串不同本身不足以证明独立性。`independence.authoring.json`保留v4–v6旧34条评测材料/家族登记的排除清单（仅22条有明确origin.case_id，不能据此断言全部有独立司法案号），v4 replication复用v4材料，没有另加独立案分母。

## 事件与检查边界

标签沿用schemaVersion3完整11字段；`events`和`expected_event_ids`仅在标注/评分侧，不进入模型输入。每个anchor定位原block.text中的金额/日期value码点范围，同额资产/欠薪/实际付款分属不同源文陈述或行为事件。不同明确陈述属性默认分event；同一直接期间可支持任职与工资两角色。

数据作者结构检查验证15家族唯一、旧案URL/family排除、11字段、连续quote/value、subject/period原文支持、日期null字段、原文块定位与hash、事件anchor无跨事件重叠。标签经主树新版候选接口与事件评分自匹配，属于结构检查，不是模型输出、稳定语义能力或业务效果证明。独立审查意见、冻结状态和真实首次运行结果另行记录。
